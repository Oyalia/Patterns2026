# TripCraft Studio: Твірні патерни проектування GoF у JavaScript

Інтерактивна система планування та бронювання подорожей на базі 5 твірних патернів проектування GoF (Creational Patterns) на чистому JavaScript.

Дизайн інтерфейсу реалізовано в інженерній HUD-естетиці: моноширинні мітки, мікро-рамки (1px grid lines), інформаційна щільність, функціональні роздільники секцій та строгий контрастний стиль.

У проєкті реалізовано всі 5 класичних твірних патернів (Creational Patterns) за класифікацією GoF у прикладній області організації та бронювання подорожей (TripCraft).

## Реалізація 5 твірних патернів GoF

### 1. Одинак (Singleton)
- **Файли:** `library/singleton/TripSession.js`, `library/singleton/TripEventBus.js`
- **Призначення:** Забезпечує наявність єдиного екземпляра класу в системі та надає глобальну точку доступу до нього.
- **Як реалізовано:**
  - Приватне статичне поле `#instance`.
  - Захист у конструкторі: повертає вже створений об'єкт при повторному виклику `new TripSession()`.
  - Статичний метод `getInstance()`.
  - `TripSession` керує активною валютою (EUR, USD, UAH) з динамічними курсами обміну (`convertPrice`, `formatPrice`), формує кошик заброньованих позицій (`addBookedItem`, `removeBookedItem`), контролює кількість мандрівників, бюджет та тему інтерфейсу.
  - `TripEventBus` записує та транслює події бронювання у реальному часі.
  - Інтерфейс включає висувний кошик подорожі (Itinerary Drawer), швидкі категорійні фільтри, поле пошуку, степер кількості туристів, HUD Toast-сповіщення та генерацію електронного ваучера мандрівника.

### 2. Фабричний метод (Factory Method)
- **Файли:** `library/creators/*` та `library/elements/*`
- **Призначення:** Визначає інтерфейс для створення об'єкта, але залишає підкласам право вирішувати, екземпляр якого класу створювати.
- **Як реалізовано:**
  - Базовий клас `TravelElementCreator` оголошує метод `create(params)` та спільний алгоритм монтування `createAndAppendTo(domElement, params)`.
  - Підкласи-творці (`HotelElementCreator`, `FlightElementCreator`, `ExcursionElementCreator`, `BookingFormElementCreator`) інкапсулюють інстанціювання відповідних продуктів.
  - Клієнтський код працює з абстрактним типом `TravelElementCreator`, не прив'язуючись до деталей конкретних елементів.

### 3. Абстрактна фабрика (Abstract Factory)
- **Файли:** `library/abstractFactory/*`
- **Призначення:** Надає інтерфейс для створення сімейств взаємопов'язаних або взаємозалежних об'єктів без зазначення їхніх конкретних класів.
- **Як реалізовано:**
  - Інтерфейс `TravelUIFactory` декларує методи генерації сімейства віджетів: кнопки (`createButton`), бейджа (`createBadge`) та картки (`createCard`).
  - Конкретні фабрики `BusinessDarkThemeFactory` (темна тема з золотисто-бурштиновими акцентами) та `ResortLightThemeFactory` (світла тема з морськими ціановими акцентами) створюють узгоджені набори компонентів.
  - `ThemeFactoryProvider` зв'язує фабрику з поточним станом синглтона `TripSession`.

### 4. Будівельник (Builder)
- **Файли:** `library/builder/*`
- **Призначення:** Відокремлює конструювання складного об'єкта від його представлення, завдяки чому один і той самий процес конструювання може створювати різні представлення.
- **Як реалізовано:**
  - Складний продукт `TravelItineraryWidget` об'єднує заголовок напрямку, дату, переліт, готель, список екскурсій, кількість мандрівників, розрахунок загальної суми та дії.
  - Клас `ItineraryBuilder` надає fluent-методи (`setDestination`, `setDates`, `setFlight`, `setHotel`, `addExcursion`, `setTravelers`, `build()`).
  - Клас `ItineraryDirector` містить алгоритми збірки готових турів: Альпійський гірськолижний тур, Середземноморський круїз та експедиція Токіо-Кіото.

### 5. Прототип (Prototype)
- **Файли:** `library/prototype/*`
- **Призначення:** Визначає види створюваних об'єктів за допомогою екземпляра-прототипу і створює нові об'єкти шляхом копіювання цього прототипу.
- **Як реалізовано:**
  - Клас `TripPackageCard` реалізує метод `clone(overrides)`. Метод виконує глибоке копіювання конфігурацій, масивів тегів і деталей, збільшуючи версію клону та дозволяючи точкові мутації.
  - Клас `TripTemplateRegistry` виступає каталогом прототипів, зберігаючи еталонні тури (Карпати, Середземномор'я, Сіті-брейк) та клонуючи їх на вимогу клієнта.
  - На кожній картці у браузері є кнопка "Клонувати пакет", яка демонструє роботу клонування прямо в інтерфейсі.

## Інтегрований проєкт (Усі патерни разом)

У файлі `script.js` реалізовано спільний сценарій (Showcase Mode):
1. **Singleton (`TripSession`)** ініціалізує параметри подорожі, валюту розрахунку та брокер аудиту.
2. **Abstract Factory (`ThemeFactoryProvider`)** створює стилізований вітальний блок хабу відповідно до поточної теми.
3. **Factory Method (`FlightElementCreator`, `HotelElementCreator`, `ExcursionElementCreator`, `BookingFormElementCreator`)** створює складові подорожі: авіарейс, номер у готелі, гірську екскурсію та форму підтвердження.
4. **Builder (`ItineraryDirector` + `ItineraryBuilder`)** покроково конструює повний пакет туру з автоматичним підрахунком фінальної вартості.
5. **Prototype (`TripTemplateRegistry`)** клонує зразок готового пакета відпочинку, модифікуючи категорію та тривалість.
6. **Singleton (`TripEventBus`)** у реальному часі записує всі операції в консоль телеметрії.

## Автоматизоване тестування

Для запуску тестів:

```bash
npm test
```

Тестовий набір містить 21 тест у 5 тестових сюїтах:
- Singleton (ідентичність екземплярів, зміна валюти, акумуляція бюджету, обробка подій);
- Factory Method (робота базового творця, створення готелів, рейсів, турів, форми, монтування в DOM);
- Abstract Factory (генерація сімейств BusinessDark та ResortLight, резолвер);
- Builder (fluent-конструювання маршруту, валідація суми, рецепти директора);
- Prototype (глибоке ізольоване клонування пакета, робота реєстру прототипів).

## Запуск веб-додатку локально

```bash
npm start
```

Або відкрийте `index.html` у браузері через будь-який локальний статичний веб-сервер:
```bash
python -m http.server 3000
```
Після запуску перейдіть за адресою: `http://localhost:3000`.
